# Carolina Heating Service — Next.js rebuild of carolinaheating.com

This is a **high-fidelity port** of the live WordPress site (NearU base theme + CHS child theme). The goal is visual and structural parity with the original, so the architecture is built around the original theme's real CSS and DOM rather than a re-interpretation.

## How the site is assembled

1. **Theme CSS (`src/app/theme.css`)** — generated by `node scripts/build-theme-css.mjs`. It fetches every page of the live site with `?nowprocket=1` (bypasses WP Rocket's minify/"remove unused CSS") and concatenates the ORIGINAL stylesheets in WordPress' exact enqueue order: WP core block styles → theme.json presets (`--wp--preset-*`) → Simple Banner plugin → `nearu-base/dist/css/style.css` → `chs/style.css` → inline @font-face/site-title → Customizer CSS → lite-youtube → promotions block. Font URLs are rewritten to `/fonts/`. **Never hand-edit theme.css**; re-run the script.
2. **Global chrome (React)** — `src/components/Header.tsx`, `Footer.tsx`, `SimpleBanner.tsx` reproduce the original `#masthead`/`#colophon`/`.simple-banner` markup and class names 1:1, driven by `content/site.json`. `Header.tsx` ports the behavior of the theme's `navigation.js` (mobile `.toggled` drawer, `data-header-nav-expanded` on `<html>`, `aria-expanded`-driven sub-menus). The SVG icon sprite (`src/lib/iconSprite.ts`, 51 icons) is inlined right after `<body>` exactly as the theme does; use `<Icon name="..."/>`.
3. **Homepage (`src/app/page.tsx`)** — hand-built in React, block-for-block against the original DOM, using the shared block components in `src/components/blocks/` (ServicesList, IconList, ImageStack, OurCommunity, MaintenanceFinancing, Certifications/LogoCarousel, GoogleReviews, YouTubeEmbed, Elevated). Copy lives in `content/pages/home.json`; WordPress' per-page layout CSS for the homepage is in `content/pages/home-inline.css`.
4. **Every other page (`src/app/[...slug]/page.tsx`)** — served from `content/html/<path>.json`, generated by `node scripts/extract-pages.mjs`. Each JSON holds the page's `<main>` inner HTML (cleaned: lazy-load placeholders removed, absolute links made root-relative, schedule buttons routed to `/bookings`, images rewritten to `/images/...`), plus `title`, `description`, `ogImage`, and `inlineCss` (WordPress' per-page `core-block-supports-inline-css` — `.wp-container-*`/`.wp-elements-*` rules whose hashes are unique per page, so they are emitted per page like WordPress does, not merged globally). `src/components/ThemeBehaviors.tsx` ports the theme's `carousel.js`, logo-carousel arrows, and lite-youtube click-to-play onto this server-rendered HTML.
5. **Images / fonts** — all self-hosted in `public/images/<year>/<month>/…` (mirrored by the extractor, preserving WP's folder structure) and `public/fonts/`. Nothing hotlinks to the old site.

## Editing content

- **Header/footer/nav/banner/business info** → `content/site.json`.
- **Homepage copy** → `content/pages/home.json` (and the block components for structure).
- **Any other page** → edit the `html` string in its `content/html/*.json` file. It is the original WordPress markup; keep the class names intact so theme.css keeps applying. File naming: route path with `/` replaced by `__` (e.g. `services__greenville-sc-heating__furnaces.json` → `/services/greenville-sc-heating/furnaces`). To add a page, add a JSON file with the same shape; the catch-all route picks it up automatically.
- **Re-sync a page from the live site** → `node scripts/extract-pages.mjs https://carolinaheating.com/<path>/`. Re-sync everything: `node scripts/extract-pages.mjs` (uses `scripts/pages.txt`, currently 105 URLs from the page/service/post sitemaps plus a few unlisted pages).
- Redirects that exist on the live site (`/contact-us` → `/about-us`, `/services/indoor-air-quality` → …) are in `next.config.ts`.

## Verification tools

- `node scripts/screenshot.mjs <url> <out.png> [w] [h] [waitMs] [clickSelector]` — full-page (or click-then-viewport) screenshot via Chrome DevTools Protocol. Use it to compare `http://localhost:3000/<path>` against `https://carolinaheating.com/<path>/`.
- `node scripts/eval.mjs <url> "<js expression>"` — evaluate JS (e.g. computed styles) in the rendered page.
- Note: the live site delays all JS until user interaction (WP Rocket), so headless screenshots of it lack the yellow banner, carousel chrome, and video poster. Those are present in a real browser and in our build.

## Not ported (external services)

- **ServiceTitan scheduler modal** — the live site's "Schedule Now" buttons call `_scheduler.show({schedulerId:'sched_oq353rja01ythqqkwhdbp5cl'})` from an external widget script. We route them to `/bookings` (which is itself a mirrored landing page). Add the ServiceTitan embed script and restore the `onclick` when ready.
- **Chat widget** ("Text us" bubble) and **cookie-consent banner** — third-party embeds not included.
- The generator landing page's Mailchimp form posts directly to Mailchimp and works without extra JS.

## Do not

- Do not add Tailwind or other CSS frameworks — the theme CSS ships its own reset and grid primitives and they conflict.
- Do not hotlink images/fonts to carolinaheating.com — Cloudflare bot protection on that origin blocks Vercel's image optimizer.
